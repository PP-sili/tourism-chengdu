# 成都文旅后端 — 功能实现说明（供前端对接）

> **发给前端同学看这份文档即可。**  
> 接口参数细节见 [API.md](./API.md)，在线调试：`http://{host}:8081/swagger-ui.html`

**说明（2026-07-28 更正）**：曾有一版文档误写「不做景点评价」。**正确需求是：景点要做评价（好评/差评/建议）；社区帖子不做评论。** 后端已按正确需求实现，请以本文档为准。

---

## ⚠️ 最重要：两套完全不同的功能

| | 景点评价 | 社区帖子评论 |
|--|---------|-------------|
| **要不要做** | ✅ **要做** | ❌ **不做** |
| **在哪里** | 景点详情页 | 帖子详情页 |
| **是什么** | 用户对**景区**的游玩反馈 | 用户在**帖子**下留言回复 |
| **类型** | 好评 / 差评 / 建议（三选一） | 无 |
| **后端接口** | `/api/evaluations`、`/api/scenes/{id}/evaluations` | **无接口** |

**一句话**：逛完景点可以写评价；看社区帖子只能点赞，**不能在帖子下面评论**。

## 一、容易搞错的地方（速查表）

| 功能点 | ❌ 不要做成这样 | ✅ 后端实际是这样 |
|--------|----------------|-------------------|
| 登录 | 短信验证码登录 | **手机号 + 密码**，返回 JWT |
| 注册 | 验证码注册 | **手机号 + 密码 + 可选昵称** |
| **景点详情页** | 只有介绍、没有评价 | **必须有评价区**：好评/差评/建议 Tab + 写评价 |
| **社区帖子详情** | 底部评论输入框、评论列表 | **无评论**，只有图文 + 点赞 |
| 景点评价类型 | 五星打分完事 | 必须选 **good / bad / suggestion** 之一，再填文字 |
| 谁能写评价 | 任何人随便评 | **去过的景区**才能评（见下文规则） |
| 评价次数 | 同一景点反复评 | **每个用户对每个景点只能评 1 次** |
| 我的页获赞 | 含评价相关 | **只统计帖子被点赞数**，与景点评价无关 |
| 门票预约 | 一单一证 | **一单多票种**，**每张票单独填身份证** |
| 支付 | 微信/支付宝 | **模拟支付**，调 `POST .../pay` 即成功 |

## 三、后端已实现的功能

### 1. 用户注册与登录

- **手机号 + 密码**，无短信验证码
- `POST /api/auth/register`、`POST /api/auth/login`
- `GET/PUT /api/user/profile`、`PUT /api/user/avatar`

---

### 2. 首页

- `GET /api/banners` — 轮播图
- `GET /api/scenes` — 景点列表
- `GET /api/weather/chengdu` — 成都天气（固定成都，无城市切换）

---

### 3. 景点导览

| 方法 | 路径 | 登录 |
|------|------|------|
| GET | `/api/scenes` | 否 |
| GET | `/api/scenes/{id}` | 否 |
| GET | `/api/scenes/{id}/visitor-stats` | 否 |
| GET | `/api/scenes/{id}/ticket-stats` | 否 |

- 免费景点（票价 0）返回 `bookable: false`，**不可预约**，但可以**写评价**（登录即可）

---

### 4. 景点评价（好评 / 差评 / 建议）⭐

#### 后端实现了什么

用户对**去过的景区**写评价，类型三选一：

| type 值 | 含义 | 前端 Tab 建议 |
|---------|------|---------------|
| `good` | 好评 | 好评 |
| `bad` | 差评 | 差评 |
| `suggestion` | 建议类 | 建议 |

- 评价内容必填，最多 500 字
- 可选 1–5 分 `rating`（不传时后端按类型给默认：好评 5、差评 2、建议 3）
- **每个用户对每个景点只能评价 1 次**

#### 谁能评价（「去过的景区」怎么判定）

| 景点类型 | 条件 |
|----------|------|
| **收费景点** | 有该景点**已支付**的门票订单，且游玩日期 **≤ 今天**（订单状态 `pending_use` 或 `used`） |
| **免费景点** | **登录即可评价**（宽窄巷子、锦里等） |

前端写评价前，先调 `GET /api/evaluations/can-evaluate?sceneId=` 判断按钮是否可点。

#### 相关接口

| 方法 | 路径 | 登录 | 说明 |
|------|------|------|------|
| GET | `/api/scenes/{id}/evaluations?type=all\|good\|bad\|suggestion` | 否 | 评价列表 |
| GET | `/api/scenes/{id}/evaluation-summary` | 否 | 各类型数量统计 |
| POST | `/api/evaluations` | 是 | 发表评价 |
| GET | `/api/evaluations/can-evaluate?sceneId=` | 是 | 是否可评 |
| GET | `/api/evaluations/mine` | 是 | 我的评价 |

#### 发表评价

```json
POST /api/evaluations
{
  "sceneId": 2,
  "type": "good",
  "content": "都江堰非常值得一游！",
  "rating": 5
}
```

`type` 只能是：`good`、`bad`、`suggestion`

#### 评价列表示例

```json
{
  "id": 1,
  "sceneId": 2,
  "sceneName": "都江堰",
  "type": "good",
  "content": "讲解专业，非常推荐",
  "rating": 5,
  "userId": 1,
  "userNickname": "熊猫爱好者",
  "userAvatar": null,
  "createTime": "2026-07-27T16:00:00"
}
```

#### 统计示例

```json
GET /api/scenes/2/evaluation-summary
{
  "goodCount": 12,
  "badCount": 3,
  "suggestionCount": 5,
  "totalCount": 20
}
```

#### 前端必须实现

- 景点详情页：**评价区域**（全部 / 好评 / 差评 / 建议 Tab）
- 展示各类型数量
- 「写评价」按钮（先调 `can-evaluate`）
- 评价表单：选类型 + 填内容 + 可选评分
- 我的页可增加「我的评价」入口

#### 前端不要实现

- ❌ 在**帖子详情**加评论区（那是另一回事，后端没接口）
- ❌ 把景点评价做成帖子评论的样式嵌在社区里

---

### 5. 门票预约与订单

- 一单可多种票（成人/学生/儿童），**每张票单独填姓名 + 身份证号**
- 模拟支付，每张票独立 JSON `qrCode` 票根
- 退票截止：游玩日前一日 20:00

详见 [API.md](./API.md)。

---

### 6. 行程

- 门票**支付成功后后端自动生成**行程
- `GET /api/itinerary` 查看，`PUT /api/itinerary/{date}` 改排序和备注
- 无「手动创建行程」接口

---

### 7. 社区（帖子）— 无评论

#### 后端实现了什么

- 发帖（最多 9 图）、列表（时间/热度）、详情、点赞、我的帖子

#### 后端没有实现

- **帖子评论、回复** — 无表、无接口

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/api/posts` | 发帖 |
| GET | `/api/posts?sort=time\|hot` | 列表 |
| GET | `/api/posts/{id}` | 详情（浏览量+1） |
| POST | `/api/posts/{id}/like` | 点赞/取消 |

热度：`点赞数×2 + 浏览量`

#### 前端必须实现

- 社区列表、帖子详情、发帖、点赞

#### 前端不要实现

- ❌ 帖子详情页底部的**评论输入框**
- ❌ 帖子下的**评论列表、回复**

---

### 8. 图片上传

- `POST /api/upload/image`（multipart，字段名 `file`）
- 用于：头像、帖子图片

---

### 9. 文创商城

- 商品、购物车、**多商品合并下单**、模拟支付
- 物流：**只展示订单状态 + 物流单号**，不对接快递 API

---

### 10. 我的（个人中心）

- `GET /api/user/overview` — 汇总（资料、帖子数、获赞数、订单统计、购物车数量）
- `totalLikes` = **帖子获赞总数**，不含景点评价
- `GET /api/evaluations/mine` — 我的评价列表

---

## 四、后端明确不提供的功能

1. 短信验证码登录/注册  
2. **社区帖子评论、回复**（注意：这与景点评价不是一回事）  
3. 真实支付、扫码核验、快递轨迹 API  
4. 管理员后台 API

## 五、页面与后端模块对应（建议）

| 页面 | 后端模块 | 有无接口 |
|------|----------|----------|
| 登录/注册 | 手机号+密码 | ✅ |
| 景点详情 — **评价 Tab** | 景点评价 good/bad/suggestion | ✅ |

| 社区发帖/点赞 | 帖子 | ✅ |

| 我的评价 | GET /api/evaluations/mine | ✅ |
